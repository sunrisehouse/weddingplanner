# weddingplanner

웨딩홀 투어를 기록하고 나란히 비교하는 웹앱.

투어 현장에서 서서 한 손으로 적는 것을 기준으로 만들었습니다.
업체와 금액을 앱이 제안하지 않고, 직접 적은 것만 저장하고 계산합니다.

## 첫 방문 — 한 화면에 질문 하나

처음 열면 질문 5개를 **한 화면에 하나씩** 물어봅니다. 전부 선택지로 고릅니다.

**묻는 건 자료의 큰 항목뿐입니다.** 체크리스트 인쇄면의 `구분` 열이 그대로 질문이 됩니다 —
웨딩홀 · 스드메 · 허니문 · 혼수. 청첩장 · DVD · 주례 · 폐백음식처럼
자료에서 **'기타'로 묶인 작은 항목은 묻지 않습니다.**

| | 질문 | 선택지 |
|---|---|---|
| 1 | 결혼식 날짜가 정해지셨나요 | 확정 / 가예약 / 아직 |
| 2 | 웨딩홀은 정하셨나요 | 계약 / 투어 중 / 아직 |
| 3 | 스드메는 어디까지 하셨나요 | 계약 / 상담 중 / 아직 |
| 4 | 허니문은 정하셨나요 | 예약 / 알아보는 중 / 아직 |
| 5 | 혼수는 어디까지 하셨나요 | 거의 정함 / 알아보는 중 / 아직 |

### 답으로 하는 일 — 언제까지 해야 하는지 알려주기

예식일과 준비 상태를 예약 시점에 대보고, **시점이 지난 것만 짚어줍니다.**

| 항목 | 앱이 안내하는 시점 | 기준 |
|------|--------------------|------|
| 웨딩홀 | 늦어도 10개월 전에 예약 | 예식일 |
| 스드메 | 10~12개월 전에 예약 | 예식일 |
| 허니문 | 6~8개월 전에 예약 | 예식일 |
| 혼수 | 예단은 3개월 전에 준비 | 예식일 |

혼수의 한복은 **촬영 2개월 전**, 가전·가구는 **입주 2~3개월 전** 기준이라
예식일로 계산하지 않고 그 사실만 알려줍니다.

무엇을 먼저 하라고 순서를 정해주지는 않습니다. **시점이 지난 것만** 짚습니다.

#### 말투 — 서비스가 안내한다, 전해 듣고 알려주지 않는다

숫자의 출처는 **박람회 자료 `비고` 열**이고, 근거는 [docs/01-checklist.md](docs/01-checklist.md)와
`app/js/store.js`의 `PREP` 주석에 남겨둡니다. 새 숫자를 추측해서 넣지 않기 위한 기록입니다.

**하지만 화면에서는 출처를 말하지 않습니다.**

| | |
|---|---|
| ✕ | "자료 기준 최소 10개월 전 예약" |
| ✓ | "늦어도 10개월 전에 예약하세요" |
| ✕ | "투어에서 물어볼 것 보기" |
| ✓ | "웨딩홀 투어 준비하기" |

앱을 쓰는 사람에게 필요한 건 **지금 뭘 하면 되는지**입니다.
어디서 본 내용인지는 우리가 관리할 문제입니다.

다음에 할 일도 앱이 정해서 버튼 하나로 줍니다 — 목록을 던져놓고 알아서 보라고 하지 않습니다.

| 웨딩홀 상태 | 다음 버튼 |
|---|---|
| 아직 안 알아봤어요 | 웨딩홀 투어 준비하기 |
| 투어 다니는 중이에요 | 투어 기록 시작하기 |
| 계약했어요 | 계약한 웨딩홀 기록하기 |

- 날짜 확정/가예약을 고르면 **날짜 입력 화면**이 이어집니다. 이 화면은 앞 질문의
  후속이라 진행 번호(`2/5`)를 차지하지 않습니다
- 예식일을 모르면 시점을 따질 수 없으니 **계산하지 않고 그렇다고 말합니다**
- 모든 질문에 **`건너뛰고 바로 시작하기`** 가 있습니다.
  건너뛴 항목은 `안 정하셨어요`로 남아 **"아직 안 알아봤다"와 구분됩니다**
- 뒤로 가기로 답을 고쳐도 되고, 끝난 뒤에도 바꿀 수 있습니다

## 홈은 전체, 항목은 탭에서

최상위 화면은 **탭 두 개**입니다. 홈에는 전체로 봐야 하는 것만 두고,
웨딩홀처럼 한 항목을 관리하는 화면은 **웨딩홀 탭**에 둡니다.

```
[ 🏠 홈 ]                      [ 💐 웨딩홀 ]        ← 하단 탭
   #/                             #/venues
   · D-day (확정 / 가예약)          · 투어 기록 목록 · 예상 합계
   · 다음에 다가오는 시점            · 비교표 (2곳 이상)
   · 준비 현황 4항목 + 답 수정        ├ #/new    기록 폼
   · 내보내기 / 불러오기              ├ #/v/:id  기록 수정
                                    └ #/guide  투어 준비
```

온보딩(`#/start/N`)은 홈의 **`답 수정`** 으로 다시 들어갑니다.
탭은 최상위 두 화면에만 붙습니다 — 기록 폼 · 투어 준비 · 온보딩은
뒤로 가기로 돌아가므로 탭을 달지 않습니다.

### 홈에 두는 것 — 전체로 봐야 하는 것만

| | |
|---|---|
| **D-day** | 예식일까지 남은 일수, 가예약이면 표시. 시점이 지난 항목을 한 줄로 |
| **다음 시점** | 아직 안 지난 마감 중 가장 가까운 것 — `10월 22일까지 예단 준비하세요 · 66일 남았어요` |
| **준비 현황** | 4항목 각각 `언제까지 무엇을` + 상태 칩 |

마감일은 **예식일에서 거꾸로 센 날짜**입니다 (`예식일 − 시점`).
`늦어도 10개월 전`처럼 기간으로만 말하지 않고 **날짜로** 알려줍니다.

준비 현황의 네 줄은 **상태만 보여주는 줄**입니다. 웨딩홀 외에는 아직 전용 화면이
없으니 화살표를 달지 않습니다 — 눌러도 아무 일 없는 버튼을 두지 않습니다.

### 웨딩홀 탭 · 기록이 0곳일 때

기록이 0곳이면 빈 비교표 대신 갈래를 나눕니다.

| | 다음 화면 |
|---|---|
| **투어 다녀왔어요** | 기록 폼 |
| **아직 안 가봤어요** | 웨딩홀 투어 준비 |
| 예시로 먼저 둘러보기 | 비교표가 어떻게 보이는지 (한 번에 지울 수 있음) |

비교표는 2곳 이상이어야 의미가 생기는데 첫 방문자는 0곳입니다.
그래서 **예시 데이터**를 넣어볼 수 있게 하고, `예시` 표시를 달아 언제든 지웁니다.

**앱 소개는 화면에 두지 않습니다.** "이 앱이 하는 일 / 안 하는 일" 목록을
깔아두면 읽을 거리만 늘고, 정작 할 일이 뒤로 밀립니다.

기록이 이 브라우저에만 저장된다는 것은 계속 말합니다 — 나중에 알면 이미 늦습니다.

## 하는 일

- 웨딩홀별로 **홀 이름 · 투어 날짜 · 홀 사용료 · 꽃장식 · 식대 · 보증인원** 기록
- 포함 여부를 **있음 / 없음 / 모름** 3단으로 선택
  (`모름`이 따로 있어야 "안 물어본 것"과 "없는 것"이 구분됩니다)
- 예상 합계 자동 계산 — `홀 사용료 + 꽃장식 + (보증인원 × 식대)`
  값이 하나라도 비면 **계산 불가**로 두고 억지로 채우지 않습니다
- 2곳 이상 기록하면 비교표가 나타납니다
- 견적서 사진 첨부
- 입력 즉시 자동 저장
- **웨딩홀 투어 준비** — 투어에서 확인할 것을 짚어주고, 확인한 그대로 비교표가 됩니다
- **예약 시점이 지난 큰 항목** 알림 (웨딩홀 · 스드메 · 허니문 · 혼수)

**앱은 순위를 매기거나 추천하지 않습니다.** 적어둔 것을 나란히 놓아줄 뿐입니다.

## 안 하는 일

| | 이유 |
|---|---|
| 시세 · 평균가 제시 | 업체 · 지역 · 시기마다 달라서, 어떤 기준값을 보여줘도 틀린 숫자를 믿게 만듭니다 |
| 업체 추천 · 평점 | 판단은 쓰는 사람이 합니다 |
| 금액 기본값 채우기 | 채워두면 결국 앱이 가격을 제안하는 셈이 됩니다 |

## 저장

**localStorage에 저장합니다.** 서버도 로그인도 없이 바로 쓸 수 있는 대신 한계가 있습니다.

| 한계 | 실제로 생기는 일 |
|------|------------------|
| 브라우저 하나에만 저장 | 다른 기기에서 못 봅니다 |
| 기기를 바꾸면 사라짐 | 폰을 바꾸면 안 따라옵니다 |
| 브라우저 데이터 삭제 시 소실 | "인터넷 사용 기록 삭제"로 날아갑니다 |
| 용량 5MB 안팎 | 사진 몇 장이면 찹니다 |

그래서 이렇게 대응했습니다.

- **JSON 내보내기 / 불러오기** — 유일한 백업이자 기기 이동 수단이라 처음부터 넣었습니다
- **사진은 IndexedDB에 분리** — localStorage는 문자열만 담기고 한도가 작아,
  사진이 텍스트 기록까지 밀어내는 것을 막았습니다
- **저장 실패 시 알림** — 용량이 차면 조용히 넘어가지 않고 알립니다
- **`store.js` 뒤로 숨김** — 앱 코드는 localStorage를 직접 건드리지 않습니다.
  서버로 옮길 때 이 파일만 교체하면 됩니다

### 여럿이 함께 보려면

localStorage로는 안 됩니다. 필요해지면 **Supabase** 무료 티어가 이 구조에 잘 맞습니다 —
정적 사이트에서 바로 붙고, anon 키는 공개돼도 되며 RLS로 접근을 막습니다.
`store.js` 하나만 바꾸면 됩니다.

## 배포

`.github/workflows/pages.yml` 이 `main` 푸시마다 `app/` 을 GitHub Pages로 올립니다.

처음 한 번만 설정이 필요합니다.

1. `Settings → Pages → Source` 를 **`GitHub Actions`** 로 변경
2. 무료 플랜에서는 저장소가 **public** 이어야 합니다

private으로 두면서 배포하려면 **Cloudflare Pages** 나 **Netlify** 를 쓰면 됩니다
(둘 다 private 저장소를 무료로 배포합니다).

> ⚠️ **개인적인 기록은 이 저장소에 두지 마세요.**
> 계약 금액, 업체명, 준비하면서 내린 결정 같은 것은 앱 안에서만 다루면 됩니다.
> 앱의 데이터는 브라우저에만 저장되고 저장소로 올라가지 않습니다.
